# Phase 6 — Cut Over

## Status
[x] Complete | Date: 2026-05-29

## Goal
Switch all infrastructure entrypoints (Docker, docker-compose, CI, Render) from the
Flask stack to Django, and prune Flask-specific dependencies from `requirements.txt`.
The Flask source code is preserved in `backend/src/` for reference but is no longer
reachable from any entrypoint.

## Changes

| File | What changed |
|---|---|
| `infra/docker/backend.Dockerfile` | CMD → Django gunicorn WSGI; `DJANGO_SETTINGS_MODULE` env var; removed `PYTHONPATH=/app/src` |
| `infra/compose/docker-compose.yml` | Added Postgres 16 service with health-check; backend depends on Postgres; command → Django gunicorn |
| `.github/workflows/ci.yml` | Test job → runs Django migrations + `pytest tests/dj`; adds Postgres service; lint targets Django modules |
| `backend/requirements.txt` | Removed Flask, SQLAlchemy, alembic; werkzeug retained for `WerkzeugPasswordHasher` |
| `backend/pyproject.toml` | `testpaths` changed from `tests` → `tests/dj` |
| `render.yaml` | Replaced Flask env vars with Django ones; added `databases` block for Render managed Postgres |

## Decisions

1. **`migrate --noinput` before gunicorn** — Both Dockerfile CMD and docker-compose
   `command` run `python manage.py migrate --noinput &&` before starting gunicorn.
   This ensures schema is always up to date on container start without a separate
   migration job, which matters during Render's rolling deploy where the old process
   may still be running.

2. **Postgres 16 in docker-compose** — The local compose stack now matches production
   (Render managed Postgres). SQLite dev database (`django_dev.db`) still works for
   `runserver` via the `DJANGO_DATABASE_URL` fallback in `settings.py`, but
   container-based local runs are now Postgres.

3. **werkzeug kept in requirements.txt** — Even though Flask is removed, werkzeug
   is still imported by `accounts/hashers.py:WerkzeugPasswordHasher.verify()` to
   check passwords migrated from Flask. Once all migrated users have logged in once
   (auto-upgraded to native Django PBKDF2), werkzeug can be removed.

4. **Flask source code not deleted** — `backend/src/` (the Flask app) is preserved
   to allow side-by-side comparison and reference during the Django burn-in period.
   It can be removed in a separate cleanup PR once the Django stack is proven stable
   in production.

5. **CI test job requires Postgres** — The test job now spins up a `postgres:16-alpine`
   service container via GitHub Actions service containers. This ensures tests run
   against the same DB engine as production rather than SQLite, catching any
   Postgres-specific ORM behavior before deploy.

6. **render.yaml `fromDatabase`** — `DJANGO_DATABASE_URL` is bound to a Render
   managed Postgres database via `fromDatabase.property: connectionString`. This
   means the connection string is injected by Render at deploy time and never
   hard-coded. The `databases` block provisions a free-tier Postgres instance named
   `financius-db`.

## Environment variables after cutover

| Variable | Purpose |
|---|---|
| `DJANGO_SETTINGS_MODULE` | `financius_web.settings` — selects the Django settings module |
| `SECRET_KEY` | Django session signing key (generated by Render) |
| `JWT_SECRET` | JWT access/refresh token signing key (generated by Render) |
| `DJANGO_DATABASE_URL` | Postgres connection string (injected by Render from managed DB) |
| `GOOGLE_CLIENT_ID` | Google OAuth client ID |
| `API_BASE_URL` | Base URL for QR pairing token links |
| `ALLOWED_HOSTS` | Comma-separated list of allowed hostnames |

## Local dev after cutover

```bash
# Start the full stack (Django + Postgres) in containers
cd infra/compose
docker compose up --build

# Or run Django directly against the SQLite dev DB (no Docker needed)
cd backend
python3 manage.py migrate
python3 manage.py runserver 8001
```

The `.env` file must contain at minimum:
```
DJANGO_SETTINGS_MODULE=financius_web.settings
JWT_SECRET=dev-secret
SECRET_KEY=dev-secret
GOOGLE_CLIENT_ID=replace-me
```

`DJANGO_DATABASE_URL` is optional locally — `settings.py` falls back to
`sqlite:///data/django_dev.db` if it is not set.
